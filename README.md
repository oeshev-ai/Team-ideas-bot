# Telegram-бот для сбора идей и задач команды

Бот принимает идеи и задачи в личке или в общем чате, сохраняет их в SQLite и умеет показывать список, искать по тексту и выгружать данные в CSV и Markdown. Данные живут в файле базы: перезапуск и сбой процесса их не стирают.

## Возможности

В **группе** бот отвечает только на `/start` и `/add`. Остальные команды молча игнорируются.

В **личке** видны задачи всех чатов, где вы состоите (участник, администратор или создатель).

| Команда | Где | Назначение |
| --- | --- | --- |
| `/start` | группа и личка | Приветствие (разный текст) |
| `/add <текст>` | группа и личка | Добавить задачу в **текущий** чат |
| `/help` | только личка | Подробная справка |
| `/list` | только личка | Открытые задачи доступных чатов |
| `/search <текст>` | только личка | Поиск по доступным чатам |
| `/export csv` / `/export md` | только личка | Выгрузка задач доступных чатов |
| `/stats` | только личка | Статистика по доступным чатам |
| `/done <ID>` | только личка | Закрыть задачу (автор или админ её чата) |
| `/delete <ID>` | только личка | Удалить задачу (админ её чата) |
| `/audit` | только личка | Журнал по чатам, где вы админ |
| `/chats` | только личка | Список доступных чатов и роль |

В группах команды можно вызывать с упоминанием бота, например `/add@your_bot Купить маркеры`.

Каждая запись хранит `chat_id`, `user_id`, `username`, текст, время создания и статус (`open` / `done` / `deleted`). Удалённые задачи не показываются в `/list` и `/search`.

## Права

Бот сам читает роли из Telegram: `getChatMember` и статусы `administrator` / `creator`. Отдельных «админов бота» нет — назначайте администраторов в настройках чата.

- Обычный участник: в группе — `/add`; в личке — список, поиск, экспорт, статистика и закрытие **своих** задач.
- Администратор или создатель чата: в личке может закрывать любые задачи этого чата, удалять их и смотреть `/audit`.
- Доступ к чату в личке проверяется через `getChatMember`: статусы `member`, `administrator`, `creator`. Результат кэшируется на 5 минут.
- Если бот не смог узнать статус (нет в чате, Forbidden, чат не найден), чат пропускается.

### Мягкое удаление

`/delete` не стирает строку из SQLite, а ставит `status='deleted'`, заполняет `deleted_at` и `deleted_by`. Такие задачи скрыты в `/list` и `/search`, но остаются в файле базы.

Восстановить вручную можно так:

```sql
UPDATE tasks
SET status = 'open', deleted_at = NULL, deleted_by = NULL
WHERE id = 12 AND chat_id = -1001234567890;
```

## Требования

- Python 3.10+
- Токен бота от [@BotFather](https://t.me/BotFather)

## Локальный запуск

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
copy .env.example .env
```

В `.env` укажите токен:

```
BOT_TOKEN=123456:ABC-your-telegram-bot-token
DB_PATH=tasks.db
LOG_LEVEL=INFO
```

`LOG_LEVEL=DEBUG` включает подробный технический лог. По умолчанию — `INFO`.

Запуск:

```powershell
python -m bot
```

То же самое: `python main.py`.

На Linux/macOS активация окружения: `source .venv/bin/activate`, копирование: `cp .env.example .env`.

## Запуск в Docker

Создайте `.env` с `BOT_TOKEN` (как выше). Файл базы будет в `./data/tasks.db` благодаря volume.

```powershell
docker compose up --build
```

Остановка:

```powershell
docker compose down
```

Том `./data:/data` сохраняет SQLite между перезапусками контейнера. `DB_PATH` внутри контейнера задаётся как `/data/tasks.db`. Технические логи пишутся в `./logs` (том `./logs:/app/logs`).

## Как пользоваться в групповом чате

1. Создайте бота у BotFather и скопируйте токен в `.env`.
2. Добавьте бота в общий чат команды и выдайте ему право читать сообщения (достаточно стандартных прав; команды работают и при включённом privacy mode).
3. Если бот не видит обычный текст, но команды обрабатывает — это нормально: все действия идут через `/add`, `/list` и остальные команды.
4. При желании в BotFather можно отключить privacy mode (`/setprivacy` → Disable), это не обязательно для текущего набора команд.

## Экспорт

- **CSV:** кодировка `utf-8-sig`, разделитель `;`, чтобы файл корректно открывался в Excel. Имя: `tasks_<chat_id>_<YYYY-MM-DD>.csv`. Колонки: `id`, `created_at`, `status`, `username`, `user_id`, `text`.
- **Markdown:** заголовок чата и список задач с ID, датой, статусом, автором и текстом. Имя: `tasks_<chat_id>_<YYYY-MM-DD>.md`.

## Журнал действий и логи

Две независимые системы.

### Технический лог (для разработчика)

Пишется одновременно в stdout и в файл `logs/bot.log`. Папка `logs` создаётся при старте.

Формат строки:

```
2026-09-21 15:04:01,123 | INFO | main | Бот запущен: @team_tasks_bot (id=123)
```

Ротация через `RotatingFileHandler`: файл обрезается после 5 МБ, хранятся 5 копий.

```
logs/bot.log      — текущий файл
logs/bot.log.1    — предыдущий (только что «переполненный»)
logs/bot.log.2
...
logs/bot.log.5    — самый старый, дальше удаляется
```

Токен бота и другие секреты в лог не попадают: они маскируются как `***`. Не включайте `BOT_TOKEN` в сообщения логгера и не коммитьте `logs/`.

### Журнал действий (аудит, для команды)

Таблица `audit_log` лежит в той же SQLite-базе (`tasks.db` / `/data/tasks.db`). Туда пишутся `/add`, `/done`, `/delete`, `/export`, `/search` и отказы в правах (`denied`).

Команда `/audit` в личке показывает последние 20 записей по чатам, где вы администратор:

```
2025-01-15 10:32 | @ivan | add #12 | Чат: Команда
2025-01-15 11:05 | @maria | done #12 | Чат: Команда
```

В группе `/audit` игнорируется. Если вы нигде не админ: «Команда доступна только администраторам чатов.» Если записей нет — бот сообщит об этом.

Ошибка записи в `audit_log` не ломает основную команду: она уходит в технический лог.

## Структура проекта

Код разложен по пакетам внутри `bot/`. Каждый пакет отвечает за одну область.

```
bot/
  __main__.py              — python -m bot
  app.py                   — сборка: логи, БД, диспетчер, polling
  config/
    settings.py            — .env, BOT_TOKEN, DB_PATH, LOG_LEVEL
    techlog.py             — технический лог и маскирование секретов
  db/
    connection.py          — соединение SQLite, PRAGMA WAL
    models.py              — Task, ChatStats
    sql.py                 — LIKE / unicode_lower
    tasks.py               — репозиторий задач (схема и CRUD)
  audit/
    models.py              — AuditEntry
    repository.py          — таблица audit_log
  permissions/
    access.py              — доступ к чатам команды и кэш названий
    cache.py               — кэш get_chat_member (60 с)
    checks.py              — кто может закрыть задачу
  export/
    common.py              — дата файла, автор, статус
    csv.py                 — CSV для Excel
    markdown.py            — Markdown
  middlewares/
    command_log.py         — лог входящих команд
  handlers/
    common.py              — справка, формат списков, audit helper
    start.py               — /start и /help в личке
    group.py               — /start и /add в группе
    add.py                 — общий хендлер /add
    tasks.py               — /list /search /done
    moderation.py          — /delete /stats /chats
    export.py              — /export
    audit.py               — /audit
    errors.py              — глобальные ошибки
main.py                    — тонкая обёртка над python -m bot
requirements.txt
.env.example
Dockerfile
docker-compose.yml
```

База создаётся при старте: таблица `tasks` (включая `deleted_at` и `deleted_by`), таблица `audit_log`, индексы `idx_tasks_chat_status` и `idx_audit_chat_created`, PRAGMA `journal_mode=WAL`, `synchronous=FULL`, `foreign_keys=ON`. Недостающие колонки на уже существующей базе добавляются автоматически.

## Надёжность

- Запись идёт в файл SQLite, а не в память процесса.
- WAL + `synchronous=FULL` снижают риск потери данных при сбое.
- Ошибки в хендлерах логируются; необработанное исключение не роняет polling-цикл.
- Если `BOT_TOKEN` не задан, процесс завершается с понятным сообщением ещё до запуска бота.
